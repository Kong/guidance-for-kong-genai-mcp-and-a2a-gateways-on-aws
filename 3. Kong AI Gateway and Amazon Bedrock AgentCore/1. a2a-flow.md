# The A2A Flow

This diagram illustrates a secure and observable Agent-to-Agent (A2A) communication architecture built using **AWS Bedrock AgentCore**, **Kong Agent Gateway**, and **Konnect** as the centralized control plane.

![A2A-Flow](../assets/images/a2a-flow.png)

The design demonstrates how multiple AI agents can communicate with one another through standardized A2A routes while Kong provides governance, authentication, telemetry, and operational control.

1. User Interaction Layer

On the left side, a User initiates requests that are handled by an AI agent running inside AWS Bedrock AgentCore.

Within the AgentCore environment there are two agents:

* Agent1
* Agent2

Each agent consumes a Kong A2A Route, representing a gateway-managed endpoint for agent-to-agent communication.

This means the agents are not communicating directly through unmanaged channels. Instead, all interactions pass through Kong-governed A2A routes, enabling:

* security enforcement,
* observability,
* authentication,
* traffic control,
* and policy management.



2. Agent-to-Agent Communication Flow

Internal Agent and External / Federated Agent Communications

Inside AWS Bedrock AgentCore:

* Agent1 sends requests toward Agent2 through the Kong-managed A2A route.
* The requests are routed downward into the Kong Agent Gateway Data Plane Node before reaching the target agent.
* On the right side, Agent3 exists outside the AWS Bedrock AgentCore boundary and also consumes a Kong A2A Route, allowing it to participate in the same governed communication framework.

This demonstrates:

* federated agent architectures,
* multi-runtime agent ecosystems,
* or cross-environment AI interoperability.

This creates a secure hub-and-spoke architecture for distributed Agentic Application Systems.


3. Kong Agent Gateway (Data Plane)

At the center-bottom is the Kong Agent Gateway – Data Plane Node, which acts as the runtime enforcement and routing layer for all A2A traffic.

The gateway contains several important plugins:

* AI A2A Proxy Plugin. This is the core plugin responsible for:
    * brokering agent-to-agent communication,
    * routing A2A protocol traffic,
    * mediating requests between agents,
    * and standardizing communication semantics.

It effectively transforms Kong into an AI-native agent communication gateway.

⸻

Key Auth Plugin

The Key Authentication Plugin secures communication between agents by enforcing:

* API keys,
* identity validation,
* and access policies.

This prevents unauthorized agents from participating in the ecosystem.

⸻

OTel Plugin

The OpenTelemetry Plugin exports:

* metrics,
* logs,
* traces,
* and distributed telemetry data.

This enables deep observability into:

* agent execution,
* inter-agent latency,
* request flows,
* failures,
* and operational performance.

⸻

5. Konnect Control Plane

At the top-right, administrators interact with the Konnect Control Plane.

The dotted management connection indicates that Konnect centrally manages:

* gateway configuration,
* A2A routes,
* plugin policies,
* authentication settings,
* and operational governance.

Konnect distributes configuration to the Kong data plane nodes without being directly involved in runtime traffic.

This separation follows the classic:

* control plane vs data plane architecture.

⸻

6. Observability and Metering

On the far right, telemetry and usage data are exported to:

OpenTelemetry Observability Stack

Provides:

* distributed tracing,
* centralized logging,
* metrics collection,
* and operational monitoring.

Konnect Metering & Billing

Tracks:

* AI traffic consumption,
* agent usage,
* API utilization,
* and potentially chargeback or quota enforcement.

⸻

Architectural Significance

This architecture demonstrates how Kong can act as an AI Agent Gateway for:

* secure agent-to-agent communication,
* multi-agent orchestration,
* federated AI systems,
* and cross-runtime interoperability.

Combined with AWS Bedrock AgentCore, the platform enables:

* governed A2A communication,
* centralized policy enforcement,
* authentication,
* observability,
* and scalable distributed agent ecosystems.

The result is a production-ready foundation for enterprise-grade multi-agent systems.
