# The LLM/GenAI Flow

The diagram illustrates a LLM/GenAI request flow where an Agent running on **Amazon Bedrock AgentCore** delegates all LLM traffic through a centralized Kong AI Gateway for governance, observability, security, and policy enforcement before reaching external model providers.

![LLM-GenAI-Flow](../assets/images/llm-genai-flow.png)

The main steps of the flow are:
1. User interacts with the AI Agent
A user sends a request to an AI application hosted inside AWS Bedrock AgentCore.
    The AgentCore runtime contains an agent (“Agent1”) responsible for orchestrating prompts, tools, workflows, and reasoning logic.
2. Agent generates LLM requests
    Inside the agent, a Kong LLM Route abstracts access to external LLM providers.
    Instead of calling providers such as OpenAI or Anthropic directly, the agent routes every LLM invocation through the Kong AI Gateway.
3. Requests are forwarded to the Kong LLM Gateway Data Plane
    The request reaches a Kong LLM Gateway Data Plane Node, which acts as the centralized AI traffic control layer.
    This layer provides consistent governance and operational controls for all GenAI traffic.
4. Kong AI Gateway applies AI-specific policies and plugins
    Before forwarding the request to an LLM provider, the gateway executes several policies and plugins, including:
    * AI Proxy Advanced Plugin
        Handles provider abstraction, model routing, authentication, retries, transformations, failover, and standardized AI request handling.
    * OpenTelemetry (OTel) Plugin
        Generates telemetry data such as traces, metrics, latency, token usage, and request spans for observability platforms.
    * AI Rate Limiting Plugin
        Enforces token, request, or consumer-level limits to control cost, prevent abuse, and protect provider quotas.
5. Konnect Control Plane manages the Gateway
    Administrators interact with the Konnect Control Plane to configure and manage the gateway centrally.
    The control plane distributes configuration and policies to the Kong Data Plane nodes, including:
    * LLM routes
    * AI plugins
    * authentication policies
    * traffic governance rules
    * observability configuration
    The dashed line between Konnect and the Data Plane represents this management and configuration synchronization channel.
6. Gateway forwards requests to external LLM providers
    After policy enforcement, the Kong AI Gateway sends the LLM request to external model providers such as:
    * OpenAI
    * Anthropic
    The gateway becomes the single controlled entry point for all outbound AI traffic.
7. Observability and metering data are exported
    Telemetry generated by the gateway is exported to:
    * an OpenTelemetry-based observability stack
    * Konnect Metering & Billing
    This enables:
    * request tracing
    * token consumption tracking
    * cost attribution
    * performance monitoring
    * auditing and compliance reporting
8. LLM responses return through the same path
    Responses from the model providers flow back through the Kong AI Gateway and then return to the AgentCore application, which processes the result and delivers the final response to the user.

Architectural Benefits

This architecture provides several important advantages for enterprise GenAI deployments:

* Centralized AI governance
* Provider abstraction and portability
* Unified observability
* Token and cost control
* Rate limiting and security enforcement
* Standardized AI access patterns
* Operational separation between control plane and runtime data plane
* Easier multi-model and multi-provider adoption

The result is a production-grade GenAI architecture where AI agents can safely consume multiple LLM providers while all traffic is centrally governed through Kong AI Gateway and Konnect.
